## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Інтерфейс revisor має дві мови, і обидві мають звучати природно й однаково називати те саме. Рядки пишуть задачі TASK-7…16, а механізм перекладу дає TASK-15 (ADR-0009). Українські рядки автор чує й править під час перевірки кожної задачі з NVDA в українському інтерфейсі. Ця задача — повна вичитка обох мов перед випуском 0.1.0, коли всі рядки MVP уже написано. Рішення ухвалено 2026-11-01 у DRAFT-14.

Рядки лежать у коді Rust, а читати код скрінрідером незручно. Тож окремий інструмент для розробки (приклад cargo, не частина revisor) виводить усі рядки в текстовий файл: для кожного рядка — ідентифікатор, англійський і український варіант, а для рядків із числом — усі форми множини. Claude звіряє рядки з глосарієм, документом «Клавіатура й меню» й посібниками Microsoft — для української (Microsoft Ukrainian Style Guide) і для англійської (Microsoft Writing Style Guide) — і пропонує правки. Автор вичитує обидві мови й погоджує правки.

Перевіряємо й правила, ухвалені для всіх задач:
- назви клавіш в українському інтерфейсі — за документом «Клавіатура й меню»;
- причини помилок, які revisor розпізнає, мають власні тексти обома мовами (що сталося, чому й що робити), а для решти revisor додає до свого речення текст Windows чи SQLite і код помилки (бриф, розділ 5);
- мовою Windows говорять лише стандартні частини Windows: вікно вибору теки, контекстне меню полів, системне меню вікна.

Джерела — у полі references.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Кожен рядок revisor має англійську й українську версії, а мовою Windows говорять лише стандартні частини Windows (вікно вибору теки, контекстне меню полів, системне меню вікна).
- [ ] #2 Інструмент для розробки (приклад cargo) виводить у текстовий файл усі рядки інтерфейсу: ідентифікатор, англійський і український варіант, а для рядків із числом — усі форми множини.
- [ ] #3 Терміни й назви команд обох мов відповідають глосарію й документу «Клавіатура й меню»; розбіжності виправлено в рядках чи в цих документах.
- [ ] #4 Українські рядки відповідають посібнику Microsoft для української, а англійські — Microsoft Writing Style Guide; автор вичитав обидві мови й погодив правки.
- [ ] #5 Назви клавіш в українських рядках відповідають документу «Клавіатура й меню», а причини помилок — правилу брифу: відомі причини мають власні тексти обома мовами, а решта — речення мовою revisor, текст Windows чи SQLite і код помилки.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Інструмент виводу рядків (#2). Рішення користувача 2026-11-06: крейт `revisor` стає бібліотекою + exe — `src/lib.rs` тримає всі модулі й `run()`, `main.rs` лише викликає `revisor::run()`. Каталог рядків — `i18n/catalog.rs`: кожен метод `Strings` з усіма значеннями переліків (нові варіанти без каталогу не збираються — макрос `all!` з вичерпним match), параметри як `{name}`, рядки з числом — для 1, 3, 5 (усі форми множини обох мов), а для команд і меню — ще й пункт меню з клавішею доступу й гарячою клавішею та текст вікна «Гарячі клавіші». Тест звіряє каталог із методами трейту. `cargo run -p revisor --example strings [файл]` пише текстовий файл.
2. Вичитка (#3, #4, #5): звірити рядки з глосарієм, документом «Клавіатура й меню», Microsoft Ukrainian Style Guide і Microsoft Writing Style Guide; перевірити назви клавіш і правило причин помилок (`failure.rs`: відомі причини — власні тексти, решта — текст Windows/SQLite і код); знайти рядки поза `Strings` (#1). Місця, де вікно саме складає речення (`report_snapshot`, підказка «{}. {hint}», заголовок «Подробиці: ім'я», «{property}: {value}», причина теки в попередженні), перевірити на порядок слів.
3. Кожну правку формулювання погодити з користувачем: по одному питанню, з варіантами й рекомендованим.
4. Внести погоджені правки в `uk.rs`/`en.rs` (і код складання речень, якщо треба), оновити тести рядків; клавіші доступу лишити дійсними (тести назв і літер), правити локально; DRAFT-16 — лише зі слова користувача.
5. Оновити глосарій і «Клавіатура й меню», якщо змінилися рядки, які вони цитують.
6. cargo test, clippy, fmt --check; перевірка з NVDA обома мовами (з дозволу користувача на клавіатуру).
7. Нотатки, підсумок, Done; не зливати й не пушити без слова користувача.
