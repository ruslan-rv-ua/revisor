## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Інтерфейс revisor має дві мови, і обидві мають звучати природно й однаково називати те саме. Рядки пишуть задачі TASK-7…16, а механізм перекладу дає TASK-15 (ADR-0009). Українські рядки автор чує й править під час перевірки кожної задачі з NVDA в українському інтерфейсі. Ця задача — повна вичитка обох мов перед випуском 0.1.0, коли всі рядки MVP уже написано. Рішення ухвалено 2026-11-01 у DRAFT-14.

Рядки лежать у коді Rust, а читати код скрінрідером незручно. Тож окремий інструмент для розробки (приклад cargo, не частина revisor) виводить усі рядки в текстовий файл: для кожного рядка — ідентифікатор, англійський і український варіант, а для рядків із числом — усі форми множини. Claude звіряє рядки з глосарієм, документом «Клавіатура й меню» й посібниками Microsoft — для української (Microsoft Ukrainian Style Guide) і для англійської (Microsoft Writing Style Guide) — і пропонує правки. Автор вичитує обидві мови й погоджує правки.

Перевіряємо й правила, ухвалені для всіх задач:
- назви клавіш в українському інтерфейсі — за документом «Клавіатура й меню»;
- причини помилок, які revisor розпізнає, мають власні тексти обома мовами (що сталося, чому й що робити), а для решти revisor додає до свого речення текст Windows чи SQLite і код помилки (бриф, розділ 5);
- мовою Windows говорять лише стандартні частини Windows: вікно вибору теки, контекстне меню полів, системне меню вікна.

Джерела — у полі references.

2. Вичитка (#3, #4, #5): звірити рядки з глосарієм, документом «Клавіатура й меню», Microsoft Ukrainian Style Guide і Microsoft Writing Style Guide; перевірити назви клавіш і правило причин помилок (`failure.rs`: відомі причини — власні тексти, решта — текст Windows/SQLite і код); знайти рядки поза `Strings` (#1). ## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-11-06. Інструмент (#2): крейт `revisor` = бібліотека (`src/lib.rs`: модулі й `run()`) + тонкий `main.rs`; каталог `i18n/catalog.rs` (`revisor::catalog()`), `cargo run -p revisor --example strings [файл]` → 387 рядків, кожен з id, en і uk; рядки з числом для 1, 3, 5; пункти меню з клавішею доступу й гарячою клавішею; текст вікна «Гарячі клавіші». Тест `the_catalog_has_every_string_of_the_trait` звіряє каталог з методами `Strings` (читає `mod.rs`), а макрос `all!` не дає пропустити варіант переліку.

Рішення користувача щодо рядків (2026-11-06): (1) англійська — американський правопис за Microsoft Writing Style Guide: canceled, License, licenses; (2) «Чекаю, доки звільниться база профілю…» → «Очікування бази профілю…»; (3) «Порівнювати знімок нема з чим: …» → «Знімок не порівняно: іншого знімка в профілі немає.» / «The snapshot was not compared: the profile has no other snapshot.»; (4) порада відомої причини після тире, а не другої двокрапки («…: немає доступу — перевірте права…»); (5) попередження «Теку … не вдалося прочитати в … знімку (…)» без повтору «теку не прочитати:»; (6) назви команд із трьома крапками мають їх і поза меню — у «Гарячих клавішах» і в «чому ні» (`Command::spoken_name`), заголовки вікон без крапок; (7) дрібні: «за цим шляхом файл, а не тека»; «не можна додати, бо revisor не може її перевірити: …» / «cannot be added because…»; en «the profile database» замість «the profile's database»; en «Spacebar»; (8) англійські атрибути — словами Провідника, як українські: data not on the device, content not indexed, with integrity checking, no background integrity scan, downloaded when opened, always on this device, online-only; (9) текст Windows чи SQLite після двокрапки — з малої літери, крім слів на дві великі (SQLite) (`in_sentence`).

Перевірено без змін: рядки поза `Strings` — лише «revisor» у заголовку головного вікна й назви клавіш, підписаних на клавіатурі (keys.rs), а заголовки вікон беруть назви команд; стандартні частини Windows — вікно вибору теки (його підказка «Виберіть теку для профілю» — наша), контекстне меню полів, системне меню. Назви клавіш uk — за документом «Клавіатура й меню» («клавішу F5», «клавіші Ctrl+N», «Клавіша Delete діє лише…»). Причини помилок (`failure.rs`): відомі коди Windows і SQLite → власні тексти, решта → текст Windows/SQLite і «(код N)». Речення, які складає вікно (звіт знімка через пробіл, «Знімки. <підказка>», «Подробиці: <ім'я>», «<властивість>: <значення>»), порядку слів не ламають. Клавіші доступу правки не зачепили; DRAFT-16 не знадобився.

Документи: «Клавіатура й меню» (нові цитати й правило трьох крапок поза меню), ADR-0012 (нова назва чекання). Скрипт NVDA task12 шукає «Очікування».

Перевірка 2026-11-06: cargo test (workspace) — усе проходить, clippy --all-targets і fmt --check чисто. Автор вичитав strings.txt (387 рядків) і правок не має. NVDA 2026.2 наживо, `tools/nvda/task17_strings.py uk` і `en`: «Гарячі клавіші» мають «Порівняти з… — Ctrl+F7» / «Compare with… — Ctrl+F7»; Ctrl+F7 без знімків — «Порівняти з…: знімків ще немає.» / «Compare with…: there are no snapshots yet.»; Ctrl+F5 першого знімка — «Знімок збережено: 22 записи. Знімок не порівняно: іншого знімка в профілі немає.» / «Snapshot saved: 22 entries. The snapshot was not compared: …»; «Про revisor» — «Ліцензія: MIT» / «License: MIT»; англійських рядків в українському інтерфейсі не чути. DoD #6: нових вікон і контролів немає.
