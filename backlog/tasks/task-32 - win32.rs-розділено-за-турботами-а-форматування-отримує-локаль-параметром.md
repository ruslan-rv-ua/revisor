## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Кандидат 8 з огляду архітектури 2026-11-05 («гіпотеза»). Остання з рефакторингів m-2; йде після TASK-31. Помилок немає, виграш — у читанні коду й у точних тестах форматування; поведінка для користувача не змінюється.

**Проблема (звірено з кодом 2026-11-07).** `crates/revisor/src/win32.rs` (1260 рядків) збирає шість турбот: мова інтерфейсу й порядок назв за локаллю; доступність (IAccPropServices, live region); фокус і рядки переліків (ListView); підклас головного вікна; форматування чисел, дат, часу й розмірів та літери атрибутів; щит, Провідник і запуск від адміністратора. Функції переліків після TASK-27 беруть `snapshot_list.rs` (11 викликів), `main_window.rs` для переліків різниці (21) і `compare_window.rs` (1). Три `thread_local` тримають протоколи, яких ніхто не перевіряє: `set_empty_text` працює лише після `subclass_list_parent`, а `bold_first_item_of_next_popup` ставить прапорець, який з'їдає `WM_INITMENUPOPUP`. Форматування бере регіональний формат користувача Windows (нульова локаль, а не мова інтерфейсу — так задумано), тож тести перевіряють лише «містить 12».

**Рішення автора (2026-11-07): усе, без зміни поведінки.**
1. `win32.rs` стає текою модулів за турботами; функції переліків — спільний підмодуль `win32` (не `snapshot_list`: їх беруть і переліки різниці, які за рішенням TASK-27 на адаптер не переводимо).
2. Форматування отримує локаль параметром: у застосунку — регіональний формат користувача, як зараз; тести закріплюють точні рядки для uk-UA та en-US.
3. Два неперевірені протоколи стають аргументами чи типами, щоб порядок не можна було сплутати; `thread_local` замінено там, де це можливо без зміни поведінки.
4. Без ADR.
