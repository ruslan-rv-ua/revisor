## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Кожну задачу з інтерфейсом перевіряють наживо з NVDA: скрипт на Python готує копію exe в тимчасовій теці з власними `data\profiles`, створює тестові профілі за схемою зі `store.rs`, тисне клавіші через `keybd_event`/`SendInput` і читає нові рядки `Speaking […]` з логу NVDA (`C:\Temp\nvda.log`, рівень IO). Поки що такі скрипти пишуть заново для кожної задачі (TASK-7, TASK-9, TASK-15, TASK-21) і лишають у тимчасовій теці сесії, де вони зникають разом із нею.

Треба зібрати спільну частину в один модуль у `tools/` (підготовка тимчасового exe й профілів, пошук вікна, клавіші з розширеним прапорцем для Delete/Home/End/стрілок/Insert, набір тексту будь-якою розкладкою, читання лише нового хвоста логу з міркувань приватності, читання полів через `WM_GETTEXT`, фокус через `GetGUIThreadInfo`), а сценарії TASK-21 (коментар під час запису знімка, знімок під відкритим вікном, видалення знімка іншого профілю під підтвердженням) зберегти як перший приклад. Пастки, які вже знайдено: під модальним вікном таймер спить і поле прогресу не зникає, тож чекати треба за часом; тека з недоступними записами дає запитання про перезапуск адміністратором після кожного знімка; для запису бази тривалістю понад секунду потрібен профіль на ~800 тис. записів без недоступних тек.

Це інструмент виконавця, а не частина застосунку: не входить у збірку й у CI, не має залежностей поза стандартною бібліотекою Python.
<!-- SECTION:DESCRIPTION:END -->
