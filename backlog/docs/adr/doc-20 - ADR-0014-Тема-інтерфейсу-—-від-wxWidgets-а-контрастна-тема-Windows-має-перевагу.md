# ADR-0014: Тема інтерфейсу — від wxWidgets, а контрастна тема Windows має перевагу

- **Статус:** прийнято
- **Дата:** 2026-11-08

## Контекст

revisor був лише світлим, а багато хто тримає Windows у темній темі; слабозорим людям і тим, хто працює вночі, світлий фон заважає (TASK-34). Класичним Win32-застосункам Microsoft темної теми не дає: документовано лише темний заголовок вікна (`DWMWA_USE_IMMERSIVE_DARK_MODE`), а контроли Windows малює світлими.

wxWidgets 3.3.4, який збирає wxDragon 0.9.24 (ADR-0001), має темну тему для Windows: `wxApp::SetAppearance` просить вигляд «як у системі», світлий чи темний. Тема спирається на недокументовані функції `uxtheme.dll`, які wxWidgets бере за порядковими номерами, як і бібліотека win32-darkmode, на якій її збудовано. Частину контролів у темній темі wxWidgets малює сам: прапорці стають owner-drawn, а рядки списку він малює через custom draw. До 3.3.2 NVDA озвучував такі прапорці як кнопки (wxWidgets #26184). ADR-0004 вимагає лише нативних контролів саме заради доступності. Контрастних тем Windows wxWidgets не враховує: кольори його темної теми фіксовані.

## Рішення

1. **Тему дає wxWidgets.** revisor просить вигляд через `SetAppearance` і власних кольорів не задає. Контроли лишаються нативними (ADR-0004): прапорець, який у темній темі малює wxWidgets, — та сама кнопка Windows, а роль і стан прапорця їй віддає `wxOwnerDrawnAccessible` (wxWidgets 3.3.2). Список і дерево — ті самі SysListView32 і SysTreeView32, яким wxWidgets лише малює рядки. NVDA каже в темній темі те саме, що у світлій (перевірено в TASK-34).
2. **Налаштування «Тема»** має значення «Як у Windows» (типове), «Світла» й «Темна» — три варіанти, які Microsoft радить для теми застосунку. «Як у Windows» — вигляд «як у системі»: wxWidgets сам іде за перемиканням теми Windows.
3. **Тема діє одразу.** revisor застосовує тему до першого вікна на старті й одразу після OK у налаштуваннях: виклик після створення вікон перефарбовує їх (wxWidgets 3.3.3–3.3.4). Фокус лишається, де був, а NVDA каже те саме, що після OK без змін: «Налаштування збережено».
4. **Контрастна тема Windows перемагає.** Поки її ввімкнено (`SPI_GETHIGHCONTRAST`), revisor просить світлий вигляд, хоч би що казала «Тема». Для wxWidgets це системні кольори, тобто кольори контрастної теми. Зміну системних кольорів помічає підклас головного вікна (`WM_SYSCOLORCHANGE` і `WM_SETTINGCHANGE` із `SPI_SETHIGHCONTRAST`), а вигляд перевіряє наступна подія idle. Це не подія вікна за ADR-0013: стану вона не змінює й нічого не каже. wxWidgets просять лише тоді, коли вигляд змінився, бо сам виклик теж змінює системні кольори головного вікна.

## Розглянуті альтернативи

- **Лише як у Windows, без налаштування.** Менше рядків, але темного revisor у світлій Windows чи світлого в темній отримати не можна. Не обрано автором.
- **Нова тема діє після перезапуску, як мова.** Так не було б ризику перемикання під час роботи. Не обрано автором: Microsoft радить показувати змінене налаштування одразу, а з «Як у Windows» перемикання самої Windows однаково перефарбовує вікна.
- **«Темна» перемагає контрастну тему.** Фіксовані темні кольори wxWidgets замінили б палітру, яку людина вибрала, щоб читати. Не обрано: це суперечить настановам Microsoft щодо високої контрастності.
- **Власні кольори revisor.** Не обрано: власні кольори ламають контрастні теми й вимагають самому малювати рядки, що wxWidgets уже робить.
- **Лише темний заголовок, який документує Microsoft.** Не обрано: темний заголовок над світлим вікном не допомагає тим, кому заважає світлий фон.

## Наслідки

Позитивні:
- Темна тема без власного малювання в revisor: усе робить wxWidgets.
- NVDA чує те саме в обох темах, а контрастна тема Windows не ламається.

Негативні наслідки й ризики:
- Темна тема спирається на недокументовані функції Windows, тож оновлення Windows може її зламати. Тоді виходом лишається «Світла», а виправлення приходить із новою версією wxWidgets.
- У темній темі прапорці й рядки списку малює wxWidgets, тож доступність там залежить від нього. Оновлення wxWidgets перевіряємо з NVDA й у темній темі (`tools/nvda/release_pass.py … dark`).
- Три вади wxWidgets 3.3.4 лишаються, і revisor їх не обходить (рішення автора 2026-11-08–09). Порожній список у темній темі не показує підказки («Знімків ще немає…», «Різниці ще немає»): `wxListCtrl::OnPaint` у темній темі зафарбовує все під останнім рядком, а в порожньому списку — разом із підказкою; NVDA її каже, бо це назва списку. Виділений вузол дерева без фокуса в темній темі ледь видно: сірий фон на темному, контраст 1,39:1 (wxWidgets #25633); з фокусом його видно добре, а рядок списку без фокуса — теж. Коли контрастну тему Windows вмикають, поки revisor відкритий у темній темі, заголовки колонок списків до перезапуску лишаються блідими: після зміни режиму wxWidgets малює їх кольором теми «Header», а не контрастної теми.
- Windows, старіша за 10 версії 1903, темної теми не має: «Темна» лишає там вікна світлими.
- Стандартні частини Windows, як-от вибір теки, мають той вигляд, який дає Windows.
