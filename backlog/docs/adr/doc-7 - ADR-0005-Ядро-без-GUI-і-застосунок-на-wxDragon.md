# ADR-0005: Ядро без GUI і застосунок на wxDragon

- **Статус:** прийнято
- **Дата:** 2026-10-30

## Контекст

Rust компілюється довго, і саме це найбільше турбувало у виборі стеку (ADR-0001). wxDragon тягне за собою wxWidgets, тож кожна збірка чи тест разом із ним важчі. Логіка revisor (знімки, сховище, порівняння) від інтерфейсу не залежить. А командному рядку, який з'явиться в 0.x, потрібна та сама логіка, але без GUI.

## Рішення

Код організовано як Cargo workspace із двох крейтів:
- **ядро** — бібліотека зі знімками, сховищем і порівнянням, без залежності від wxDragon;
- **застосунок** — exe на wxDragon, який використовує ядро.

Командний рядок згодом стане окремим крейтом поверх ядра.

## Розглянуті альтернативи

- **Один крейт із модулями.** На старті простіше, але кожна перевірка й тест ядра тягне за собою wxDragon, а межу між логікою та інтерфейсом тримати важче. Не обрано.
- **Окремі крейти для сканера, сховища, порівняння й застосунку.** Межі чіткі, але на старті це зайва церемонія. Не обрано.

## Наслідки

Позитивні:
- Ядро збирається й тестується швидко, без wxWidgets.
- Зміни лише в інтерфейсі не перезбирають ядро.
- Командний рядок отримає ту саму логіку без GUI.

Негативні наслідки й ризики:
- Межу треба пильнувати: ядро нічого не знає про wxDragon, а застосунок не містить логіки знімків.
