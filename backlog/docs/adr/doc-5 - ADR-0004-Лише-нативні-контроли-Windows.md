# ADR-0004: Лише нативні контроли Windows

- **Статус:** прийнято
- **Дата:** 2026-10-30

## Контекст

revisor має бути доступним для скрінрідерів. wxWidgets здебільшого доступний «з коробки», але лише там, де використовує нативні контроли Windows. Частину контролів на Windows wxWidgets малює самостійно, і зі скрінрідерами вони працюють гірше: DataViewCtrl (зокрема DataViewListCtrl і DataViewTreeCtrl), TreeListCtrl, Grid, PropertyGrid. VirtualList із wxDragon — власний віджет, складений з панелей. Різниця може налічувати мільйони рядків (знімок до ~1 млн файлів).

## Рішення

Інтерфейс будуємо лише з нативних контролів Windows. Для списків — ListCtrl, а для великих списків — у віртуальному режимі. Для дерев — TreeCtrl. Для решти — стандартні нативні елементи. DataViewCtrl, DataViewListCtrl, DataViewTreeCtrl, TreeListCtrl, Grid, PropertyGrid і VirtualList із wxDragon не використовуємо.

## Розглянуті альтернативи

- **Вирішувати по ходу:** брати будь-які контроли й виправляти проблеми доступності, коли вони з'являться. Не обрано через ризик переробок.

## Наслідки

Позитивні:
- Скрінрідери працюють із нативними контролами без додаткових зусиль: озвучують рядки, рівні дерева, стани.
- Віртуальний ListCtrl тримає дуже великі списки, тож різниця на мільйони рядків не гальмує.

Негативні наслідки й ризики:
- TreeCtrl не має колонок, тож дані зміни в дереві показуємо текстом вузла або в подробицях «було → стало».
- Зручні генеровані віджети недоступні, наприклад PropertyGrid для налаштувань. Діалоги налаштувань складаємо зі стандартних контролів.
