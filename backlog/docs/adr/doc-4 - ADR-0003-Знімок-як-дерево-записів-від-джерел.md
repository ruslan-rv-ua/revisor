# ADR-0003: Знімок як дерево записів від джерел

- **Статус:** прийнято
- **Дата:** 2026-10-30

## Контекст

Поки revisor знімає лише файлову систему. Колись, можливо в далекій версії, можуть з'явитися знімки реєстру, і для них треба заздалегідь залишити можливість. Не хочеться, щоб тоді довелося переробляти порівняння й перегляд різниці (список і дерево). Знімки зберігаються в SQLite (див. ADR-0002).

## Рішення

Знімок складається із записів, які дають джерела. Поки джерело одне — файлова система, реєстр згодом стане ще одним. Запис — це вузол дерева: шлях у межах джерела, вид (контейнер чи елемент: тека чи файл, ключ чи значення) і атрибути, специфічні для джерела. Порівняння й перегляд різниці працюють із цією спільною моделлю. Схема бази має номер версії для міграцій.

## Розглянуті альтернативи

- **Модель суто під файли й лише номер версії схеми.** Зараз простіше, а для реєстру схему згодом розширили б міграцією. Не обрано: порівняння й перегляд різниці тоді довелося б переробляти.

## Наслідки

Позитивні:
- Реєстр додається як нове джерело, без переробки порівняння й перегляду різниці.
- Номер версії схеми дає змогу мігрувати бази знімків під час оновлень програми.

Негативні наслідки й ризики:
- Узагальнення ускладнює модель уже зараз, коли джерело лише одне.
- Узагальнення не повинно сповільнювати знімки з мільйоном записів.
- Частина правил специфічна для джерела, як-от ідентифікатор файлу NTFS для переміщень чи версія exe/dll. Тож модель має дозволяти джерелу власні правила порівняння.
