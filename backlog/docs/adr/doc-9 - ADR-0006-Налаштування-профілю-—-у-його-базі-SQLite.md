# ADR-0006: Налаштування профілю — у його базі SQLite

- **Статус:** прийнято
- **Дата:** 2026-10-31

## Контекст

Профіль — іменований набір тек із винятками й налаштуваннями, у якого є власний перелік знімків. Його налаштування — назва, теки й винятки, а в 0.x додасться опція хешу вмісту. Знімки кожного профілю зберігаються в окремій базі SQLite в теці `data` (ADR-0002), і схема бази має номер версії для міграцій (ADR-0003). Програма портабельна: усі дані лежать у теці `data` поруч з exe.

## Рішення

Налаштування профілю зберігаються в його базі SQLite разом зі знімками. Профіль — це один файл бази в теці `data`.

## Розглянуті альтернативи

- **Окремий текстовий файл на профіль** (наприклад, TOML) поруч із базою. Його можна читати й правити вручну та передати без знімків. Не обрано: два файли на профіль доводиться узгоджувати під час перейменування, копіювання й видалення, ручна правка може зламати файл, а в нього були б власні версії формату й міграції.
- **Один спільний файл налаштувань програми** для всіх профілів. Усі профілі в одному місці. Не обрано: профіль перестає бути самодостатнім, і щоб його перенести, потрібні база й частина спільного файлу.

## Наслідки

Позитивні:
- Профіль — один файл: його можна скопіювати, перенести чи видалити цілком, і налаштування не розійдуться зі знімками.
- Налаштування мігрують разом зі схемою бази, тож окремий формат із власними версіями не потрібен.
- Зміни налаштувань записуються транзакцією.

Негативні наслідки й ризики:
- Налаштування можна переглянути й змінити лише в revisor, а не в текстовому редакторі.
- Налаштування не передати окремо від знімків: копія файлу бази містить і всі знімки.
- Зміни налаштувань у новій версії програми теж потребують міграції схеми.
- Загальні налаштування програми (мова тощо) не належать жодному профілю, тож для них потрібне окреме місце. Його визначає ADR-0007.
