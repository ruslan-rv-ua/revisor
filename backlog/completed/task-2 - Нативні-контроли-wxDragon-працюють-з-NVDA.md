## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Інтерфейс revisor будуємо лише з нативних контролів Windows (ADR-0004). Ще до MVP, поки змінити підхід дешево, треба переконатися, що wxDragon дає все потрібне для доступного інтерфейсу: великі списки, дерево, меню з гарячими клавішами, фонову роботу з прогресом.

Код перевірки — окремий приклад (example) у workspace; у застосунок його не переносимо. Перевіряє автор вручну з NVDA.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Узгоджено з користувачем 2026-10-30 (по одному питанню).

1. Гілка `feature/task-2-nvda-controls` від `develop`.
2. Приклад `crates/revisor/examples/nvda_controls.rs` (запуск `cargo run --example nvda_controls`, release — `cargo run --release --example nvda_controls`). У застосунок код не переносимо. Написи англійською.
3. Одне вікно з меню; порядок Tab: підпис + віртуальний ListCtrl → підпис + TreeCtrl → кнопка Start → смуга прогресу (Gauge) і текст стану → кнопка Cancel. Кожен контрол має підпис (StaticText перед ним), щоб NVDA читав назву.
4. Віртуальний ListCtrl (`ListCtrlStyle::Report | Virtual | SingleSel`): 1 000 000 синтетичних рядків, колонки Path, Change, Size, Modified; текст генерується з номера рядка в колбеку `set_virtual_text_callback`.
5. TreeCtrl із синтетичними теками: вузли до 5 рівнів, діти додаються в `ItemExpanding` (до розгортання вузол має «плюс» через `set_item_has_children`).
6. Меню з гарячими клавішами (через `\t` у назві пункту): File → Exit (Ctrl+Q); View → Go to list (Ctrl+1), Go to tree (Ctrl+2), Go to row… (Ctrl+G, діалог номера рядка); Work → Start (F5), Cancel (Shift+F5); Help → About (F1).
7. Фонова робота: потік ~20 с, прогрес в `Arc<AtomicU32>`, скасування через `Arc<AtomicBool>`; UI опитує стан таймером (~100 мс) і оновлює Gauge та текст стану. Список і дерево під час роботи доступні.
8. Перевірки: `cargo build --example nvda_controls`, clippy (`--all-targets`), fmt, тести workspace.
9. Покрокові інструкції для користувача (NVDA) по кожному критерію; його відгуки, проблеми й обхідні шляхи — у нотатки задачі. Критерії NVDA відмічаю лише після його підтвердження.
10. Рев'ю, підсумок, коміти англійською; злиття в `develop` і пуш — лише за згодою користувача.

Уточнення під час реалізації: смуга прогресу (Gauge) не є зупинкою Tab, тому стан роботи дублюється в полі «Job status» (TextCtrl лише для читання) — до нього можна дійти Tab і прочитати. Коли кнопку Start чи Cancel вимикаємо, а фокус був на ній, фокус переходить на другу кнопку, щоб не загубитися.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Приклад `crates/revisor/examples/nvda_controls.rs` зібрано без додаткових фіч wxdragon (`default-features = false` вистачає для ListCtrl, TreeCtrl, Gauge, меню, діалогів, Timer). Release-exe прикладу — 4,3 МБ. Фонову роботу UI опитує таймером (100 мс): `wxdragon::call_after` вимагає `Send`, а віджети не `Send`, тож атомарні змінні + таймер простіші.

Перевірка з NVDA (користувач, 2026-10-30, release-збірка прикладу): «Усе працює». Підтверджено: віртуальний список на 1 млн рядків прокручується стрілками, Page Up/Down, Home/End і переходом Ctrl+G без затримок, NVDA читає рядки й позицію; дерево з лінивим заповненням NVDA озвучує з рівнем і станом «згорнуто/розгорнуто»; пункти меню читаються з гарячими клавішами, а клавіші спрацьовують; фонова робота не зависає інтерфейс, скасовується, стан прогресу NVDA читає.

Проблеми доступності та обхідні шляхи: під час перевірки нових проблем не знайдено. Застосовані заздалегідь прийоми, які варто перенести в MVP: (1) Gauge не є зупинкою Tab — стан роботи дублюємо в TextCtrl лише для читання; (2) назва контрола — StaticText безпосередньо перед ним у порядку створення; (3) перед вимкненням кнопки з фокусом фокус переносимо на інший контрол; (4) прогрес із фонового потоку — через атомарні змінні й таймер UI.

Рев'ю (стандарти + відповідність задачі): порушень CLAUDE.md, ADR-0004 і ADR-0005 немає. Виправлено після перевірки з NVDA: гонка в `poll` (`progress` читався до `finished`, і смуга могла застигнути на 199/200); «Cancelled at 100%», коли скасування приходило після останнього кроку (тепер підсумок за фактичним кроком); числа в написах беруться з `ROW_COUNT`; передачу фокусу між кнопками винесено в `swap_enabled`. Відоме й прийняте для прикладу: `Rc`-цикл «таймер ↔ JobUi» тримає таймер живим до кінця програми — у застосунку власником таймера має бути вікно. Після виправлень test, clippy -D warnings, fmt --check чисті.

DoD #5: бриф і ADR не змінювалися — перевірка підтвердила ADR-0004, рішень вона не змінила.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Додано приклад `crates/revisor/examples/nvda_controls.rs` (`cargo run --release --example nvda_controls`) для ручної перевірки нативних контролів wxDragon з NVDA. У застосунок код не перенесено.

Що в прикладі:
- віртуальний ListCtrl (Report | Virtual | SingleSel) на 1 000 000 синтетичних рядків із колонками Path, Change, Size, Modified; перехід до рядка за номером (Ctrl+G);
- TreeCtrl із синтетичними теками до 5 рівнів, діти додаються під час розгортання (`ItemExpanding` + `set_item_has_children`);
- меню з гарячими клавішами: Ctrl+Q, Ctrl+1, Ctrl+2, Ctrl+G, F5, Shift+F5, F1;
- фонова робота ~20 с в окремому потоці: прогрес і скасування через атомарні змінні, UI опитує таймером 100 мс, стан показують Gauge і поле «Job status» (TextCtrl лише для читання, зупинка Tab).

Результат: користувач перевірив з NVDA — усі критерії виконано, проблем доступності не знайдено. Висновок для MVP: ADR-0004 підтверджено, wxDragon із `default-features = false` дає все потрібне. Прийоми для MVP записано в нотатках (підпис StaticText перед контролом, дублювання прогресу в полі для читання, передача фокусу перед вимкненням кнопки, таймер замість `call_after`).

Перевірки: cargo test --workspace, cargo clippy --workspace --all-targets -D warnings, cargo fmt --check — чисті. Рев'ю (стандарти + відповідність задачі) виправлено: гонка прогресу в `poll`, хибне «Cancelled at 100%», жорстко прописані числа, дубль передачі фокусу. Release-exe прикладу — 4,3 МБ.

Ризики: виправлення після рев'ю (лише кінець фонової роботи й написи) з NVDA повторно не перевірялись.
