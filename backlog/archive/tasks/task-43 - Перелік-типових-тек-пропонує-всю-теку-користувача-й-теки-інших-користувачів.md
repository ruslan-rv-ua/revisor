## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
У переліку типових тек (TASK-36) від теки користувача є лише дві частини: AppData й робочий стіл. Інсталятори й програми пишуть і в інші місця профілю (Documents, Saved Games, теки на кшталт `.config` у корені профілю), і щоб узяти ці зміни, теку користувача доводиться додавати вручну. Крім того, коли перелік відкривається, тека Windows позначена, а вона велика: до знімка потрапляє багато записів, хоча програми туди здебільшого не пишуть. Також бувають програми, які пишуть у профілі інших облікових записів (наприклад, інсталятор від імені адміністратора, запущений з облікового запису звичайного користувача). Додати ці теки з переліку зараз не можна.

Етап: 0.5 (m-6).

Вирішено з користувачем (2026-11-13):
- **Тека користувача.** До набору додається восьма тека, «Тека користувача» (FOLDERID_Profile, тобто `%USERPROFILE%` цілком). «AppData користувача» й «Робочий стіл користувача» лишаються, щоб можна було взяти лише їх. Набір перестає бути набором тек, які одна одну не містять: перелік показує й теки, що лежать усередині іншої теки цього самого переліку. Під час додавання ширша тека замінює вужчі, як це вже відбувається з вкладеними теками профілю (TASK-36). Правило, що теки, які вже охоплює тека профілю, у переліку не показано, лишається.
- **Позначки.** Коли перелік відкривається, «Тека користувача» й Windows не позначені, а решта тек позначені.
- **Інші користувачі.** Облікові записи беруться з реєстру `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList` (ProfileImagePath). Показуються лише справжні користувачі, тобто SID `S-1-5-21-…` (локальні й доменні) і `S-1-12-1-…` (Microsoft Entra). Системних профілів (SYSTEM, LocalService, NetworkService), поточного користувача й записів, теки яких немає на диску, не показано. Назва запису — ім'я теки профілю: вона є завжди, навіть для видаленого доменного запису, ім'я якого Windows уже не знайде. Кожен запис дає три рядки без позначок: тека користувача, AppData, робочий стіл. Ці рядки стоять у кінці переліку, після тек поточного користувача, записи впорядковано за абеткою, а три рядки запису йдуть поспіль.
- **Налаштування.** Теки інших користувачів є в переліку лише тоді, коли у вікні «Налаштування» увімкнено прапорець «Показувати теки інших користувачів у переліку типових тек». За замовчуванням він вимкнений.

Вкладка налаштувань (вирішено 2026-11-13): прапорець «Показувати теки інших користувачів у переліку типових тек» стоїть на вкладці «Знімки» вікна «Налаштування» (TASK-44).

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Ядро (`typical.rs`): восьма тека Profile; порядок — Program Files, (x86), ProgramData, Windows, загальний робочий стіл, далі трійка поточного користувача (тека користувача, AppData, робочий стіл) — так вирішено з користувачем 2026-11-13. Кандидат несе власника (поточний чи інший користувач). `offer` показує й вкладені теки, але кожне місце лише раз; `add` пропускає вужчі теки, які вже охоплює ширша. Позначка за замовчуванням: усе, крім теки користувача, Windows і тек інших користувачів.
2. Інші користувачі: ProfileList з реєстру (RegGetValueW розгортає REG_EXPAND_SZ), чиста функція вибору записів (SID S-1-5-21-…/S-1-12-1-…, не поточний, тека є на диску, без дублікатів шляху), впорядкування за ім'ям теки, по три рядки на запис.
3. Налаштування `show_other_users_folders` (за замовчуванням вимкнено) у settings.rs, прапорець на вкладці «Знімки» з клавішею &O, передавання значення у вікно профілю.
4. Вікно переліку: позначки за замовчуванням, назви рядків інших користувачів; рядки обома мовами в i18n і catalog.
5. Тести ядра, налаштувань і вікна налаштувань; cargo test/clippy/fmt.
6. Перевірка з NVDA обома мовами (за згодою користувача), документи: бриф, README (обидва), «Клавіатура й меню».

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Виконання (2026-11-13):
- Порядок поточного користувача вирішено з користувачем: Program Files, (x86), ProgramData, Windows, загальний робочий стіл, далі тека користувача, AppData, робочий стіл — як трійки інших користувачів після них.
- Ядро (`typical.rs`): `Typical { folder, user, path }`; `offer` пропускає вже наявні місця за точним збігом (а не за охопленням), тож вкладені теки показано; `add` пропускає теку всередині вже доданої ширшої й замінює вужчі, у будь-якому порядку вибору. `Offered::checked_at_first`.
- Інші користувачі: ProfileList через RegOpenKeyExW/RegEnumKeyExW/RegGetValueW (REG_EXPAND_SZ розгортається); чиста `other_users` (SID S-1-5-21-…/S-1-12-1-… лише з цифр — `.bak`-копії відкинуто; не поточний; тека є; без дублікатів шляху; за абеткою без урахування регістру).
- Знахідка: без прав адміністратора revisor не відкриває `C:\Users\<інший>` (Access denied), тож таких рядків немає. Вирішено з користувачем: над списком рядок «Теки інших користувачів видно лише від імені адміністратора.» (і в повідомленні «Усі типові теки вже є в профілі.», якщо вікна немає). `others_out_of_reach` перевіряє PermissionDenied. На цьому комп'ютері (користувач deliro) — true.
- Налаштування `other_users_folders` (за замовчуванням false), прапорець «Показувати теки інших користувачів у переліку типових тек (&O)» на вкладці «Знімки».
- cargo test (448 тестів), clippy, fmt --check — чисто. Документи: бриф, README обома мовами, «Клавіатура й меню», «Клавіші доступу», CHANGELOG.

Перевірка з NVDA 2026.2 (2026-11-13, скрипт `tools/nvda/task43_typical_folders.py`):
- Без прав адміністратора, uk і en — `all heard`: 7 рядків із назвою, шляхом і станом; Windows і тека користувача «не позначено», решта «позначено»; тека користувача, позначена разом з AppData й робочим столом, додається сама (5 тек у профілі, без запитання); Alt+O на вкладці «Знімки» перемикає прапорець, NVDA читає назву й стан, Enter зберігає; з прапорцем рядків deliro немає, а рядок про права є у вікні й читається NVDA+B. Сам NVDA рядка під час відкриття не читає: так налаштовано (reportObjectDescriptions = False); список і далі названо «Теки».
- Від імені адміністратора (запускав користувач, uk): NVDA прочитав «Тека користувача deliro», «AppData користувача deliro», «Робочий стіл користувача deliro» — усі «не позначено». Підсумкового рядка скрипта я не бачив, лише мовлення в журналі NVDA.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Перелік типових тек тепер пропонує й «Теку користувача» (%USERPROFILE%) поруч з AppData й робочим столом. Порядок: Program Files, (x86), ProgramData, Windows, загальний робочий стіл, далі трійка користувача. Коли перелік відкривається, тека користувача й Windows не позначені. Вкладені теки показано; позначена ширша тека додається без вужчих і замінює теки профілю всередині себе.

Новий прапорець «Показувати теки інших користувачів у переліку типових тек (O)» на вкладці «Знімки» (типово вимкнений) додає в кінець переліку по три рядки без позначок на кожен обліковий запис із ProfileList (SID S-1-5-21-…/S-1-12-1-…, не поточний, тека є на диску), за абеткою. Без прав адміністратора ці теки відкрити не можна, тож вікно каже «Теки інших користувачів видно лише від імені адміністратора.» (вирішено з користувачем).

Перевірка: cargo test, clippy, fmt; NVDA обома мовами без прав і українською від імені адміністратора. Документи: бриф, README обома мовами, «Клавіатура й меню», «Клавіші доступу», CHANGELOG.

Обмеження: робочий стіл іншого користувача береться як <профіль>\Desktop; перенесений (наприклад, в OneDrive) робочий стіл іншого користувача в переліку не з'явиться.
